# ADR 0014: Own portable Core Data Sources without runtime state or credentials

- Status: Accepted
- Date: 2026-08-29

## Context

NetBox's Core API combines one writable configuration model with several operational and generated surfaces. Data
Sources describe how NetBox obtains external files. Data Files are generated by synchronizing a Data Source; Jobs,
Object Changes, and background queue/worker/task endpoints record runtime activity; Object Types are local application
metadata; Config Revisions and Auto-Sync records are internal implementation state.

Data Source parameters are backend-defined and may contain credentials. The built-in Git backend mixes the portable
branch selector with username/password fields, while the Amazon S3 backend uses access-key parameters. A Data Source
URL can also embed credentials or a signed query string. Copying the raw parameter object or an unsafe URL into
immutable evidence would cross the collector's secret boundary. Replacing a destination's parameter object with a
redacted source object would also destroy locally provisioned credentials.

## Decision

Add a selectable **Core data sources** dataset containing `core.DataSource`. It owns name, backend type, source URL,
enabled state, sync interval, ignore rules, description, comments, Owner, and the built-in Git branch parameter. Name
is the portable natural identity. The destination must provide the selected backend type before apply.

The collector rejects Data Source URLs containing user information, a query string, or a fragment. It never emits the
raw backend parameter object: only the Git branch is projected. The target adapter applies the same projection, so
credentials never appear in comparisons. During writes, the owned Git branch is reconciled while every other existing
destination parameter remains intact. Synchronization status, last-synced timestamp, generated files, Jobs, Object
Changes, Object Types, Config Revisions, Auto-Sync records, and background worker state are not collected or applied.

The dataset uses the existing immutable observation, typed DiffSync preview, append-only review, target revalidation,
permission check, and transactional `source.sync_to(target)` path. The comparison engine advances because the
supported resource graph changed; the provider implementation remains at the pre-release version `0.0.1`.

## Consequences

- A reviewed comparison can create or update portable Data Source configuration without copying credentials.
- Destination secrets and plugin-specific backend parameters survive updates unchanged.
- New private Git or S3 Data Sources require credentials to be provisioned independently on the destination.
- Generated content and historical/operational records continue to be produced by the destination itself.
- Data Sources using credential-bearing or signed URLs must be converted to destination-local parameters before they
  can be collected.
